# Azul Airgapped Deployment: Start to Finish

This repo is intended to deploy two Argo CD applications:

| Argo app | Chart path | Namespace | Values file |
|---|---|---|---|
| `azul-infra` | `infra/` | `azul-infra` | `infra/values.yaml` |
| `azul` | `azul/` | `azul-app` | `azul/values.yaml` |

The current deployment expects external DNS to resolve the browser-facing names and expects the Azul web TLS certificate to be provided manually or generated by the helper script.

## 1. Prerequisites

On the deployment/admin workstation:

```bash
kubectl
helm
argocd CLI, optional
openssl
jq
curl
```

In the cluster:

- Argo CD installed.
- An ingress controller matching `ingressClassName: nginx` in the values files, or update the values to your ingress class.
- Storage class matching `storageClassName: longhorn`, or update both values files to your storage class.
- Container images and Helm dependency charts available to the airgapped cluster.
- DNS records for the endpoints you intend to use.

Default local endpoint names currently used by the values/scripts:

```text
azul.local
keycloak.local
opensearch-dashboards.local
minio.local
minio-api.local
rancher.local
longhorn.local
argocd.local
```

For a company environment, replace these with your real DNS names in:

```text
infra/values.yaml
azul/values.yaml
infra/scripts/configure-keycloak-azul.sh variables, or env overrides
```

## 2. Prepare values

Use only these active values files for Argo deployment:

```text
infra/values.yaml
azul/values.yaml
```

Historical/example files may remain in the repo for reference, but Argo should not reference them.

Important Azul app values:

```yaml
web:
  ingress:
    enabled: true
    hosts:
      - azul.local
    ingressClassName: nginx
    secretName: azul-external-web-tls

security:
  oidc:
    enabled: true
    authority_url: https://keycloak.local/realms/azul
    client_id: azul-web

pluginsEnabled: false
```

Important infra values:

```yaml
certManager:
  enabled: true

keycloak:
  ingress:
    hostname: keycloak.local

opensearch:
  dashboard:
    ingress:
      host: opensearch-dashboards.local

minio:
  main:
    ingress:
      api:
        host: minio-api.local
      console:
        host: minio.local
```

## 3. Create required Kubernetes secrets

Create infra secrets first:

```bash
cd /data/azul-app
infra/scripts/create-k3s-infra-secrets.sh
```

For production/airgap, set explicit secret values instead of accepting defaults/generated values, for example:

```bash
export S3_ACCESS_KEY='...'
export S3_SECRET_KEY='...'
export KEYCLOAK_ADMIN_PASSWORD='...'
export KEYCLOAK_DB_PASSWORD='...'
export OPENSEARCH_ADMIN_PASSWORD='...'
export OPENSEARCH_DASHBOARD_PASSWORD='...'
infra/scripts/create-k3s-infra-secrets.sh
```

Then create Azul app secrets:

```bash
azul/scripts/create-k3s-app-secrets.sh
```

For production/airgap, set explicit app secret values:

```bash
export REDIS_PASSWORD='...'
export OPENSEARCH_AZUL_WRITER_PASSWORD='...'
export OPENSEARCH_AZUL_SECURITY_PASSWORD='...'
export JWT_SIGNING_SECRET='...'
azul/scripts/create-k3s-app-secrets.sh
```

## 4. Create Azul external web TLS secret

The Azul web ingress uses this secret:

```text
azul-app/azul-external-web-tls
```

### Company-provided certificate path

If your company provides a certificate and private key, use them directly:

```bash
AZUL_HOSTNAME=azul.your-company.example \
TLS_CERT_FILE=/path/to/company-fullchain.crt \
TLS_KEY_FILE=/path/to/company.key \
scripts/create-azul-external-web-tls.sh
```

The certificate must contain a SAN for the Azul web hostname.

### Local/homelab fallback path

If no company certificate is provided, the script can generate a local cert signed by the infra CA:

```bash
AZUL_HOSTNAME=azul.local \
INGRESS_IP=192.168.10.111 \
scripts/create-azul-external-web-tls.sh
```

For company DNS and trusted company PKI, you should not need Windows hosts-file or local CA installation.

## 5. Deploy with Argo CD

Apply the infra app first:

```bash
kubectl apply -f argocd/azul-infra-application.yaml
```

Wait for infra to become healthy/synced:

```bash
kubectl -n argocd get application azul-infra
kubectl -n azul-infra get pods
```

Then apply the Azul app:

```bash
kubectl apply -f argocd/azul-application.yaml
```

Wait for Azul to become healthy/synced:

```bash
kubectl -n argocd get application azul
kubectl -n azul-app get pods
```

## 6. Configure Keycloak for Azul

After Keycloak is running and reachable, configure the Azul realm, OIDC clients, roles, groups, and test users:

```bash
KEYCLOAK_URL=https://keycloak.local \
AZUL_URL=https://azul.local \
OPENSEARCH_DASHBOARDS_URL=https://opensearch-dashboards.local \
infra/scripts/configure-keycloak-azul.sh
```

For company DNS names, override the URLs:

```bash
KEYCLOAK_URL=https://keycloak.your-company.example \
AZUL_URL=https://azul.your-company.example \
OPENSEARCH_DASHBOARDS_URL=https://opensearch.your-company.example \
infra/scripts/configure-keycloak-azul.sh
```

## 7. Configure OpenSearch security/OIDC

After OpenSearch and Keycloak are both ready:

```bash
infra/scripts/configure-opensearch-security-azul.sh
```

Use environment overrides if your URLs/names differ.

## 8. Validate deployment

Check core resources:

```bash
kubectl -n azul-infra get pods,svc,ingress,secrets
kubectl -n azul-app get pods,svc,ingress,secrets
kubectl -n azul-app get secret azul-external-web-tls
```

Check ingress certificates:

```bash
openssl s_client -connect azul.local:443 -servername azul.local </dev/null 2>/dev/null | openssl x509 -noout -subject -issuer -dates -ext subjectAltName
openssl s_client -connect keycloak.local:443 -servername keycloak.local </dev/null 2>/dev/null | openssl x509 -noout -subject -issuer -dates -ext subjectAltName
```

From a browser/client with DNS resolution and trusted PKI:

```text
https://azul.local/ui/
https://keycloak.local/
https://opensearch-dashboards.local/
https://minio.local/
```

## 9. Deployment order summary

```bash
cd /data/azul-app

# 1. Create secrets
infra/scripts/create-k3s-infra-secrets.sh
azul/scripts/create-k3s-app-secrets.sh

# 2. Create Azul web TLS secret, company-cert example
AZUL_HOSTNAME=azul.your-company.example \
TLS_CERT_FILE=/path/to/company-fullchain.crt \
TLS_KEY_FILE=/path/to/company.key \
scripts/create-azul-external-web-tls.sh

# 3. Deploy infra, wait healthy
kubectl apply -f argocd/azul-infra-application.yaml
kubectl -n azul-infra get pods -w

# 4. Configure Keycloak after Keycloak is available
KEYCLOAK_URL=https://keycloak.your-company.example \
AZUL_URL=https://azul.your-company.example \
OPENSEARCH_DASHBOARDS_URL=https://opensearch.your-company.example \
infra/scripts/configure-keycloak-azul.sh

# 5. Deploy Azul app, wait healthy
kubectl apply -f argocd/azul-application.yaml
kubectl -n azul-app get pods -w

# 6. Configure OpenSearch security
infra/scripts/configure-opensearch-security-azul.sh
```

## 10. Notes for airgapped/company deployment

- Keep only `infra/values.yaml` and `azul/values.yaml` wired into Argo.
- Do not commit private keys, generated passwords, or company certificates unless your internal policy explicitly allows it.
- Prefer company DNS over hosts-file entries.
- Prefer company PKI certificates over local self-signed CA bundles.
- Ensure the Azul web certificate is stored as `azul-app/azul-external-web-tls`, because the Azul ingress references that exact secret name.
- If changing hostnames, update both ingress host values and OIDC redirect URLs.
